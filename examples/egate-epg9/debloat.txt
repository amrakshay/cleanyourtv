# NEVER DISABLE com.jm.jmlauncher ON THIS FIRMWARE. Verified on 30 October 2026: disable it, force-stop
# the stock launcher and press HOME, and the projector lands on com.android.tv.settings/.system.FallbackHome
# — Android's blank placeholder — with the stock launcher still enabled and still resolving as the HOME
# handler. It simply does not start. Both packages run in the shared user android.uid.system (uid 1000)
# and come from the same vendor (JmLauncher, JMFactory), so the "HTC" launcher is a front for JM code
# rather than a self-contained app. Re-enabling com.jm.jmlauncher brings the home screen straight back.
# It is left in the list below, commented out, so nobody adds it again.
#
# com.master.apps and com.google.android.tvrecommendations were suspected with it and are cleared:
# each was disabled on its own, with the launcher force-stopped and HOME pressed, and the home screen
# started normally. Both are active in the list.
#
# All 22 below are applied and the home screen starts. On the unit this list was written from, the
# eight /data packages among them were afterwards uninstalled outright rather than left disabled
# (README.md says which, and how they were backed up first); they are kept in the list because on
# another unit they will still be installed.
#
# All 22 below are applied and the home screen starts. Apply a list like this in batches with a HOME
# press between them: that is how the one bad package gets found without a mystery.
#
# Stock launcher: com.htc.htclauncherhighenglishd08 (nothing to do with HTC; it is the only app on
# the device that answers HOME, so disable.sh will refuse to disable it until another one is

# that Home is the quickest improvement here, before or instead of building a new launcher.

# Unknown vendor packages with no user interface
# com.abc.ninja lives in /system/app/NetflixNinja and is GRANTED both INSTALL_PACKAGES (the
# privileged one, not the "ask the user" REQUEST_INSTALL_PACKAGES) and WRITE_SECURE_SETTINGS, has
# INTERNET and a boot receiver, and registers no launcher activity. Granted, not just requested:
# it can install an app without a prompt, and it can write enabled_accessibility_services, which is
# how a dormant accessibility service gets switched on. It is the single best reason to run this list.
com.abc.ninja
com.master.apps                   # /system/priv-app/AllApp. SYSTEM_ALERT_WINDOW + boot receiver, one
                                  # bare MainActivity. Tested on its own: the home screen is fine without it.

# Accessibility-service packages
# No accessibility service is enabled right now (`settings get secure enabled_accessibility_services`
# is null). An accessibility service is how an installer taps "Install" for itself, and two packages
# here hold the permission to be switched on later, so both stay off.
com.mbox.accessibility             # /system/app/NetFocus, already disabled from the factory. Named
                                   # for accessibility; it does NOT request BIND_ACCESSIBILITY_SERVICE.
                                   # Listed so restore.sh leaves it disabled.
com.master.accessibility           # /data, installed 2025-10-14. Requests BIND_ACCESSIBILITY_SERVICE,
                                   # REQUEST_INSTALL_PACKAGES, SYSTEM_ALERT_WINDOW and a boot receiver.
